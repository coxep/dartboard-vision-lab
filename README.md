# Dartboard Vision Lab

An OpenCV prototype for continuous dartboard calibration, three-camera
rectification and dart scoring.

[View the current pipeline](https://dartboard-vision-lab.spunky-cabin-7615.chatgpt.site/)

## Current approach

Each camera is aligned independently to the same metric board plane. The script
remeasures the board pattern every frame and combines the dart observations
across cameras to estimate the hit.

1. **Seed the plane warp.** Use the approximate mount pose or previous accepted
   homography. This resolves orientation and the repeated sector pattern.
2. **Align the observed grayscale pattern.** Normalize local contrast and use
   multiscale grayscale template registration for a coarse alignment. Then refine an
   eight-parameter homography using locally contrast-normalized image appearance.
   The objective aligns observed pixels to the canonical board template.
3. **Verify the fit.** Independently check distributed grayscale junctions and
   measured edge-normal profiles on both treble and both double boundaries,
   including the outer double edge. Sparse junction refits are validation only;
   they do not replace the final appearance transform.
4. **Rectify actual pixels continuously.** Remeasure on every frame, recover after
   movement, and pause scoring when alignment is lost. Refresh the temporal
   background when alignment changes.
5. **Locate and score the dart.** Threshold settled-frame changes, retain shaft
   candidates, and jointly select axes across cameras. Their supported intersection
   gives the hit and score. Close wire calls and ambiguous intersections require
   review.

Calibration operates on grayscale intensities without binary segmentation. Its
multiscale local-template responses, subpixel localization and radial/cyclic
pattern checks borrow general principles from modern checkerboard detection.
OpenCV's [sector-based checkerboard detector](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)
uses localized Radon responses approximated by box filters and a rectangular grid.
**This dartboard detector is not a port of that Radon response or of
`findChessboardCornersSB`.** It uses normalized grayscale template correlations
for junction validation, then direct appearance registration for the final warp.
Dart detection separately thresholds before/after frame differences.

The final plane fit does not require camera intrinsics. Significant radial lens
curvature still needs a nonlinear correction: a homography alone cannot represent
it. You may supply K/D for undistortion; automatic general nonlinear warping is
not implemented. Each camera aligns independently; the shaft intersection combines
views. Saved board photographs, ORB descriptors and optical flow are not required.

Raised wires are an **optional model**, not a prerequisite for starting the
planar detector. `--wire-height-mm 1 --wire-width-mm 0.8` enables a triangular-prism
spider template with those assumed dimensions and the nominal camera centres
from `--geometry-prior`. Surface paint stays at Z=0. Raised junctions are modelled
at their height, rather than incorrectly treating every highlight as surface
paint. Intrinsics are not needed for this correction if the plane homography,
camera centre relative to the board, and feature height are known. Centre/height
errors remain sources of uncertainty. Many visible boundaries reduce random
occlusion errors; elevated-feature parallax can also introduce systematic bias.

[Three synthetic views and their actual rectifications](raised_wire_evidence/three_views.jpg)
are generated by `python validate_raised_wires.py`. The renderer projects an
actual 3D wire mesh over a textured board plane and adds a simplified 3D dart.
It uses depth-sorted triangles, without cast shadows or photorealistic optics.
The [OBJ mesh](raised_wire_evidence/spider_mm.obj) is in millimetres. No SolidCraft
integration or measured wire dimensions are claimed.

A [three-dart sequence averaged across the three rectified cameras](three_dart_evidence/average_after_3.jpg)
is generated with `python render_three_darts.py`. The
[comparison image](three_dart_evidence/comparison_after_3.jpg) includes each source
rectification. Equal weights apply to valid camera pixels; warp padding is
excluded. Raised shafts and flights remain ghosted because their projections
are above the scoring plane.

## Install

Python 3.10 or newer. Use a desktop OpenCV build for the live display.

```sh
python -m pip install -r requirements.txt
```

## Camera setup and board geometry

Input order is **upper left, upper right, bottom**. The board is upright with 20
at the top, and camera images are upright.

The nominal setup in `measured_setup/scene.json` places each lens approximately
14.75 inches (374.65 mm) from the bull across the board plane and 8.5 inches
(215.9 mm) in front of the scoring surface. Camera azimuths are approximate.
Update those positions to match the mounts. Coordinates are x right, y up and
z toward the player; the scoring plane is Z=0.

Automatic calibration requires `--geometry-prior` to seed scale and orientation.
The initial mount/orientation prior resolves the repeating sector pattern.
Recovery searches around that belief; this is not unconstrained discovery of an
arbitrarily oriented board in a room.

Match the model to the physical boundaries used for calibration:

- `--board-profile strip10`: nominal strip/blade profile, radii
  97.4 / 107.4 / 160 / 170 mm.
- `--radii TREBLE_IN TREBLE_OUT DOUBLE_IN DOUBLE_OUT`: supply measured radii
  instead. These override the named profile.

Paint edges, wire apexes and wire outside edges are distinct physical references.
An 8 mm inside-to-inside measurement is not the same as 10 mm apex-to-apex strip
spacing. The script retains `legacy8` as its default for the existing synthetic
fixtures; choose the board profile explicitly for your setup.

## Optional lens calibration

When lens correction is needed, supply one OpenCV pinhole-calibration NPZ per camera. Each file contains:

- `K`: 3×3 intrinsic matrix.
- `D`: OpenCV distortion coefficients.
- `image_size`: `[width, height]` used for that calibration.

Keep source order, resolution, crop and focus/zoom consistent with calibration.
Lens parameters stay fixed when only the camera mount moves. The supplied
synthetic coefficients are illustrative, not measurements of your C920 cameras.
The OpenCV fisheye model is not supported by this loader.

## Run

Calibrate the board, inspect continuous rectification alone, then run scoring:

```sh
python dartboard.py calibrate --sources 0 1 2 --board-profile strip10 --geometry-prior measured_setup/scene.json
python dartboard.py track-board --sources 0 1 2 --log board_tracking.jsonl
python dartboard.py run --sources 0 1 2
```

Sources can be USB indices, network stream URLs or video paths. Local cameras
must be attached to the computer running the script; network streams can be
remote. No hardware is accessed until you run a camera/stream command.

For saved images, use `--images left.jpg right.jpg bottom.jpg`; add `--once` to
`track-board` or `run`. `--headless` hides the dashboard. Ctrl+C stops execution.
`--manual` enables an optional four-click calibration fallback.

Start with an empty board. Throw **one dart at a time**, then wait for the result.
Existing darts remain part of the reference state; simultaneous additions are
ambiguous and may be rejected. Pause before retrieving darts.

| Key | Action |
| --- | --- |
| P | Pause for dart retrieval |
| R | Refresh the background and resume |
| G | Toggle the scoring grid |
| S | Save a snapshot |
| Q | Quit |

The scoring command writes estimates and review/rejection reasons to JSONL, with
frames and masks under `dartboard_output/`. The calibration-only command reports
fresh detections, loss and recovery without scoring.

## Replay recordings

Use the saved calibration with three recordings and explicit reference/settled
frame indices for each throw. Per-camera indices account for synchronization
offsets. See `examples/replay_events.json`.

```sh
python replay_recordings.py --sources left.mp4 right.mp4 bottom.mp4 --calibration calibration.json --events examples/replay_events.json --output recording_validation
```

Optional truth labels or hit coordinates are evaluated after detection and are
not supplied to the estimator. This tool replays event windows; it does not
establish automatic live throw timing.

## Validation status

The current direct-template implementation has been exercised on synthetic raised-wire
inputs with camera movement, partial occlusion and uneven lighting. The original
photo also has a boundary-check fixture; it is not synchronized multi-view footage. Synchronized
recordings from the actual C920 setup are still needed to assess real-camera
accuracy and live scoring reliability. Synthetic inputs use a textured board
plane and a simplified projected 3D dart with lens distortion, blur, noise and
JPEG compression; they do not reproduce real hands, lighting or depth occlusion.

Run the regression checks with:

```sh
python -m unittest -q test_pipeline test_detection test_recording_replay test_board_pattern test_wire_geometry
```
